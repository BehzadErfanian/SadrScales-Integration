# SadrScales.Integration v1.1.0

> Vendor-Ready additive release candidate for software vendors integrating with **Sadr Scales 5.2.1**. Not published yet.

Historical `v1.0.0` remains immutable.

## Supported baseline

- Sadr Scales: **5.2.1** or a later release explicitly documented as compatible.
- SDK target: `netstandard2.0`.
- Package consumers proven in CI: .NET Framework 4.8 and modern .NET.
- SQL validation: disposable SQL Server 2022.
- License: MIT.

## Additive capabilities

### Catalog

- Store read/upsert;
- Item Group read/upsert;
- Item/PLU read/upsert/bounded batch;
- logical PLU delete with recovery-friendly individual read;
- read-only Price History.

### Registered scales

- static scale metadata;
- coarse SQL `Online / Offline / Unknown` status;
- Item AutoSend resend request;
- supported HotKey AutoSend resend request;
- request success means resend state recorded, not physical-device completion.

### Scale configuration

- canonical multi-group Scale Assignments;
- validated per-scale Item Mapping;
- validated Mapping Copy;
- group HotKey templates;
- atomic Replace semantics;
- internal/system HotKey rows remain private and preserved.

### Sales and reports

- existing ID-ascending destination-owned Sales Feed;
- separate newest-first filtered/paged Sales Query;
- complete-filter Summary;
- distinct invoice count by `(DeviceNo, FID)`;
- weight/quantity semantics aligned with 5.2.1;
- Today, Saturday-week and Persian-month period helpers;
- typed Daily / Scale / Item reports.

### Structured invoices

- lookup by aggregate `TotalBarcode`;
- lookup by `ScaleID + FID`;
- complete header/detail result;
- lookup never auto-ACKs;
- explicit idempotent ACK after destination Save/Commit;
- acknowledged invoice remains fully readable with `AlreadyRead`.

## Developer assets

## Demo Data safety

Demo generation/reset requires:

1. clearly non-production database name;
2. required Sadr Scales 5.2.1 schema;
3. empty business data before marker initialization/generation;
4. exact database-name confirmation;
5. valid Demo marker.

Demo scales are disabled/offline and use reserved IDs plus TEST-NET addresses. Reset removes demo business rows while preserving schema, marker and default Store/Group rows.

DemoLab does **not** promote production scale lifecycle or synthetic-sale creation into the production SDK contract.

## Vendor Acceptance gate

`1.1.0` adds a package-only external-developer acceptance application with **no ProjectReference** to SDK source.

The CI flow packs the same `SadrScales.Integration 1.1.0` package a vendor receives, restores the acceptance app from that local package and executes against disposable SQL Server 2022:

```text
Validate Contract
→ Store / Group / Item
→ synthetic fixture Scale
→ Assignments / Mapping / HotKeys
→ Status / Resend
→ Sales Feed / Query / Reports
→ Structured Invoice lookup
→ destination Save + Commit
→ ACK
→ AlreadyRead full recovery
→ logical Item delete / recovery read
```

This gate complements unit tests, SQL integration tests, net48 package-consumer validation, WinForms Sample build and Public Repository Guard.

## Compatibility

`1.1.0` is additive over `1.0.0`. Existing Basic Item/Sales Feed consumers should not need to rewrite their existing integration to consume the new package.

After the final exact-head RC gate passes and PR #20 is merged, public API/contract naming is frozen for this release. Before vendor outreach, only bug, security, compatibility and non-contract documentation corrections are permitted.

## 5.3 follow-up

A typed per-scale Command Mailbox is planned for Sadr Scales 5.3 and intentionally does not delay this 5.2.1 Vendor-Ready baseline.

## Security boundary

The public SDK/repository does not expose proprietary PLUS/LSG/Aclas wire protocols, raw packets/captures, private firmware, private keys, customer production data or arbitrary Runtime commands.
