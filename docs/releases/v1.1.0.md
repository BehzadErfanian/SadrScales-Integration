# SadrScales.Integration v1.1.0

> Development release notes for the next Vendor-Ready additive release. This version is not published yet.

The `1.1.0` line extends the stable `1.0.0` integration surface additively for software vendors integrating with **Sadr Scales 5.2.1**.

Historical `v1.0.0` remains immutable.

## Supported baseline

- Sadr Scales: **5.2.1** or a later release explicitly documented as compatible.
- SDK target: `netstandard2.0`.
- Proven consumer compatibility: .NET Framework 4.8 package consumer and modern .NET.
- SQL integration validation: disposable SQL Server 2022 CI database with synthetic data only.
- License: MIT.

## Completed Vendor-Ready additions so far

### Structured Invoice lookup and explicit ACK

- lookup by aggregate `TotalBarcode` or `ScaleID + FID`;
- complete `SADR_Total` header and `SADR_Detail` rows;
- lookup never changes acknowledgement state;
- `FoundUnread / AlreadyRead / NotFound` semantics;
- an acknowledged invoice remains fully readable for recovery/re-import;
- explicit idempotent ACK sets `SADR_Total.LableStatus = 1` only after the destination chooses to acknowledge;
- destination software must Save/Commit its own data before ACK.

### Registered scales, coarse status and AutoSend resend requests

- registered scale list/read through `client.Scales`;
- coarse SQL-visible `Online / Offline / Unknown` status;
- business-useful static scale metadata without protocol state;
- Item AutoSend resend request without exposing `LastSendItem`;
- supported HotKey AutoSend resend request without exposing `LastSendKey`;
- `Requested` means the SQL resend state was recorded, not that physical transfer already completed;
- unsupported automatic behavior reports `UnsupportedModel` instead of false success.

### Stores and catalog completion

- Store list/read/upsert with `StoreCode` as stable identity;
- Item Group list/read plus semantic upsert;
- Item list/read APIs with active-only default and explicit include-deleted option;
- idempotent logical item delete through `DeleteFlag = 1`, never physical row deletion;
- deleted PLUs remain individually readable for recovery/inspection;
- read-only per-PLU and recent Price History APIs;
- no invented rule requiring every external item price update to create a PriceLog row.

### Scale assignments, per-scale mapping and group HotKeys

- canonical multi-group assignments through `client.ScaleAssignments`;
- atomic assignment replacement with `NotFound / Unchanged / Replaced`;
- per-scale PLU / ItemCode / optional HotKey-position mapping through `client.ScaleMappings`;
- mapping replacement validates duplicate PLUs, ItemCodes, positions and target layout before replacing data;
- mapping copy validates the destination first and leaves incompatible destinations unchanged;
- user-managed group HotKey templates through `client.HotKeys`;
- zero/negative internal/system HotKey rows are hidden and preserved;
- actual configuration changes request only the appropriate later AutoSend re-evaluation;
- unchanged Replace operations do not create unnecessary resend requests.

### Filtered sales query, summary and reports

- existing `Sales.ReadAfterAsync` remains the ID-ascending destination-owned synchronization feed;
- new `client.Sales.QueryAsync(filter)` provides newest-first search/report paging without touching the feed cursor;
- filters: inclusive Start, exclusive End, exact Identify, PLU, Scale ID / DeviceNo and FID;
- page number/page-size normalization matches Sadr Scales 5.2.1, including the 50..2000 page-size range;
- every query page returns complete-filter `RecordCount`, distinct-invoice count, price, weight and quantity summary;
- invoice count is distinct `(DeviceNo, FID)` rather than raw row count;
- unit codes 0/1/3 contribute to weight; Unit 2 contributes to quantity;
- `SadrSalesPeriod` reproduces Today, Saturday-based CurrentWeek and Persian-calendar CurrentMonth boundaries;
- typed reports through `client.Reports.GetDailyAsync`, `GetByScaleAsync` and `GetByItemAsync`;
- Item report remains capped at 5000 rows, matching 5.2.1;
- Query and all reports share exactly the same filter semantics and are read-only.

## Developer assets added so far

- C# Invoice SDK under `client.Invoices`;
- C# scale/status/resend SDK under `client.Scales`;
- Store/catalog APIs under `client.Stores`, `client.ItemGroups` and `client.Items`;
- configuration APIs under `client.ScaleAssignments`, `client.ScaleMappings` and `client.HotKeys`;
- filtered sales query under `client.Sales` and typed reports under `client.Reports`;
- Raw SQL recipes for invoice ACK, scale/status/resend, catalog, configuration and sales query/reports;
- Persian and English guides for all implemented Vendor-Ready slices;
- growing WinForms Developer Sample with Invoices, Scales, Catalog, Assignments/Mapping/HotKeys and Sales/Reports flows;
- disposable SQL Server integration tests for sanctioned writes and important read/aggregation/recovery semantics;
- .NET Framework 4.8 package-consumer coverage for the public SDK surface.

## Compatibility

`1.1.0` is intended to be additive over `1.0.0`. Existing `1.0.0` basic Item/Sales consumers should not need to rewrite their existing integration merely to move to the new package.

Final compatibility claims are frozen only at the 1.1.0 RC gate.

## 5.3 follow-up

A typed per-scale Command Mailbox is planned for Sadr Scales 5.3. It is intentionally outside the immediate 5.2.1 Vendor-Ready release and must not delay software-vendor outreach readiness.

## Security boundary

This public SDK does not expose direct PLUS/LSG/Aclas/device wire protocols, raw packets, packet captures, firmware, private keys, customer data or private Sadr Scales runtime source.
