# SadrScales.Integration v1.1.0

> Development release notes for the next Vendor-Ready additive release. This version is not published yet.

The `1.1.0` line extends the stable `1.0.0` integration surface additively for software vendors integrating with **Sadr Scales 5.2.1**.

Historical `v1.0.0` remains immutable.

## Supported baseline

- Sadr Scales: **5.2.1** or a later release explicitly documented as compatible.
- SDK target: `netstandard2.0`.
- Proven consumer compatibility: .NET Framework 4.8 package consumer and modern .NET.
- SQL integration validation: disposable SQL Server 2022 CI database with synthetic data only.
- License: MIT.

## Completed Vendor-Ready additions so far

### Structured Invoice lookup and explicit ACK

- lookup by aggregate `TotalBarcode`;
- lookup by `ScaleID + FID`;
- complete `SADR_Total` header and `SADR_Detail` rows returned to the caller;
- lookup never changes acknowledgement state;
- unread invoice returns `FoundUnread`;
- previously acknowledged invoice still returns complete data with `AlreadyRead`;
- missing invoice returns `NotFound`;
- explicit invoice ACK is idempotent;
- first ACK returns `Acknowledged` and sets `SADR_Total.LableStatus = 1`;
- repeated ACK returns `AlreadyAcknowledged`;
- destination software must Save/Commit its own data before ACK.

### Registered scales, coarse status and AutoSend resend requests

- read all registered scales through `client.Scales.GetAllAsync()`;
- read one registered scale by Scale ID;
- read coarse SQL-visible `Online / Offline / Unknown` status;
- expose business-useful static scale metadata without exposing internal protocol state;
- request Item AutoSend resend through the public SDK without exposing `LastSendItem`;
- request HotKey AutoSend resend where supported without exposing `LastSendKey`;
- `Requested` explicitly means the SQL request was recorded, not that physical transfer already completed;
- PLUS automatic HotKey resend returns `UnsupportedModel` instead of false success.

### Stores and catalog completion

- Store list/read/upsert with `StoreCode` as stable identity;
- Item Group list/read while retaining the existing semantic upsert;
- Item list/read APIs with active-only default and explicit include-deleted option;
- idempotent logical item delete through `DeleteFlag = 1`, never physical row deletion;
- deleted PLUs remain individually readable for recovery/inspection;
- read-only per-PLU and recent Price History APIs;
- no invented contract requiring every external item price update to create a PriceLog row.

### Scale assignments, per-scale mapping and group HotKeys

- canonical multi-group assignments through `client.ScaleAssignments`;
- complete atomic assignment replacement with `NotFound / Unchanged / Replaced` results;
- real assignment changes request Item AutoSend re-evaluation without exposing the internal watermark;
- per-scale PLU / ItemCode / optional HotKey-position mapping through `client.ScaleMappings`;
- mapping replacement validates duplicate PLUs, duplicate ItemCodes, duplicate HotKey positions and the target scale layout before replacing data;
- mapping copy validates the destination layout first and leaves an incompatible destination unchanged;
- real mapping changes request both Item and HotKey AutoSend re-evaluation;
- user-managed group HotKey templates through `client.HotKeys`;
- public HotKey APIs manage only positive-PLU user rows;
- zero/negative internal/system HotKey rows are hidden from the public read surface and preserved during replacement;
- real group HotKey changes request HotKey AutoSend re-evaluation only for scales canonically assigned to that group;
- unchanged Replace operations do not create unnecessary resend requests.

## Developer assets added so far

- C# Invoice SDK surface under `client.Invoices`;
- C# scale/status/resend SDK surface under `client.Scales`;
- C# Store API under `client.Stores` plus completed Group/Item read surface;
- C# configuration APIs under `client.ScaleAssignments`, `client.ScaleMappings` and `client.HotKeys`;
- Raw SQL structured-invoice lookup/ACK recipe;
- Raw SQL scale/status/resend recipe with writes disabled by default;
- Raw SQL catalog recipe with writes disabled by default;
- Raw SQL assignment/mapping/HotKey recipe with writes disabled by default and system-row preservation;
- Persian and English guides for invoice, scale/status/resend, catalog and configuration behavior;
- growing WinForms Developer Sample with Invoices, Scales, Catalog and Assignments/Mapping/HotKeys flows plus guarded writes;
- disposable SQL Server integration tests for sanctioned writes and important read/recovery semantics;
- .NET Framework 4.8 package-consumer coverage for the public SDK surface.

## Planned before 1.1.0 release

The release is not considered Vendor-Ready until the remaining approved 5.2.1 SQL integration surface is completed and the release gate passes, including:

- sales query/summary and reports;
- seeded Demo Data with production-database guard;
- complete WinForms Developer Sample;
- external-developer-style end-to-end acceptance test;
- final documentation cleanup and RC freeze.

## Compatibility

`1.1.0` is intended to be additive over `1.0.0`. Existing `1.0.0` basic Item/Sales consumers should not need to rewrite their existing integration merely to move to the new package.

Final compatibility claims are frozen only at the 1.1.0 RC gate.

## 5.3 follow-up

A typed per-scale Command Mailbox is planned for Sadr Scales 5.3. It is intentionally outside the immediate 5.2.1 Vendor-Ready release and must not delay software-vendor outreach readiness.

## Security boundary

This public SDK does not expose direct PLUS/LSG/Aclas/device wire protocols, raw packets, packet captures, firmware, private keys, customer data or private Sadr Scales runtime source.
